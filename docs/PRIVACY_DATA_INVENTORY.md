# 隐私数据流盘点（商店声明底稿）

状态：基于仓库源码的初步盘点，尚未经过发布负责人、法律顾问、商店控制台或最终二进制验证。此文件不是面向用户的隐私政策，也不能直接代替 Google Play Data safety 或 App Store 隐私标签申报。

盘点范围：当前 `codex/full-project-closure` 分支中的桌面端、Android Kivy 应用和 iOS IKEv2 配套应用。源码搜索未发现 Sentry、Firebase Analytics、Crashlytics、广告 SDK 或其他常见分析 SDK 的集成；这只代表静态源码检查结果，不代表所有传递依赖或构建产物均已扫描。

## 本地凭据和生命周期

- Android `profile.enc` 使用应用内 Java helper 调用 Android Keystore AES-GCM；旧 `profile.json` 迁移后重试删除，Android backup 关闭。Android 服务状态文件不持久化账号密码。APK/Keystore 真机恢复、卸载重装和系统备份行为尚未验收。
- macOS 桌面账号密码存入当前用户钥匙串；Windows 桌面密码使用 DPAPI 密文写入配置。不同桌面平台的其他设置文件仍可能包含网络名称、认证服务器地址和用户偏好。
- iOS IKEv2 密码存入设备专属 Keychain 项；VPN 配置由 iOS 系统管理。导入文件需由用户通过本地 AirDrop/USB 等安全渠道交付并在导入后删除。
- 仓库中未见开发者账户、跨设备账号、云端用户资料库或自建遥测/崩溃上报接口。该结论基于代码检查，仍需检查依赖、最终包权限与真实网络请求。

## 上架前必须完成的核对

- 确定数据控制者/发布主体名称、隐私联系地址、适用地区、隐私政策托管 URL 和数据请求/删除渠道；这些业务身份信息不能从代码推断。
- 用最终签名 Android 包检查依赖 SDK、权限和所有出站域名；真机抓包确认联网探测、Dr.COM 登录、保活、更新及用户选择的服务。
- 依据 Google Play 的定义，评估所有传出设备的用户数据类型，包括由 SDK 或第三方处理的数据；不能因为开发者没有自建后端就直接声明“不收集”。
- 对 App Store VPN 版本，发布主体需核实组织账号资格，并在首次使用前提供与实际网络行为一致的披露和隐私承诺。
- 核实认证服务器、路由器/NAS 端点能否使用 HTTPS；若学校服务仅支持 HTTP，须评估替代做法和明确的用户风险提示。
- 在真实商店账号中完成 Data safety、隐私标签、权限/前台服务声明，并确认商店页面、应用内披露、实际包和网络行为一致。
